# AI Slide Deck Design Protocol (PPTX Edition)

이 문서는 AI 슬라이드 덱(Rose Gold & Black) 프로젝트를 "순수 네이티브 PPTX 파일"로 생성하기 위해, **AI가 쓸 `PptxGenJS` 자바스크립트 코드 규칙**을 정의합니다.

## 1. 지상 과제 (The Golden Rule)
- **🔥 인텐시브 인포메이션 (수치화된 Content Density +50%)**: 현재보다 슬라이드 당 다루는 정보량을 50% 이상 폭증시킵니다.
  - **[정량적 기준]** 기존(글자수 약 100~150자, 도형 5~7개) -> **변경(글자수 최소 250~400자 이상, 도형/아이콘/이미지 총합 12~20개 이상 의무화)**. 
  - 내용이 부족할 경우 문맥에 맞는 비즈니스적 구체화, 사례, 세부 항목을 직접 추론하여 창작/추가 배치합니다.
- **🖼️ 시각적 요소(사진/픽토그램) 최대로 인젝션**:
  1. **실사 이미지(Image) 활성화**: 슬라이드 성격에 맞는 실제 사진을 `addImage`를 통해 반드시 1장 이상 적극적으로 삽입합니다. (스탁 이미지 소스: `https://images.unsplash.com/photo-...?auto=format&fit=crop&w=800&q=80`)
  2. **촘촘한 다량의 픽토그램/아이콘**: 텍스트 단락 앞이나 카드 UI 내부에 PPT 네이티브 도형(`ShapeType`)을 조합한 고퀄리티 아이콘을 다수 배치하여 텍스트의 가독성을 극대화합니다.
- **풍부한 도형 레이아웃 조합**: 원형(ellipse), 모서리가 둥근 사각형(roundRect), 선(line), 기호, 방향키(arrow) 등을 복잡하게 겹쳐서 입체감 있는 UI 카드를 설계하십시오.
- **무인 연속 진행의 원칙**: 사용자의 추가 개입을 요구하지 않고 1번부터 13장까지의 슬라이드 코드 전면 재작성을 한 번에 끝까지 수행(Auto-Proceed)합니다.

## 2. 디자인 시스템 (Design System for PPTX)

### 2.1 Colors (색상) - **[V15 개정] 대상(Dong-A) 5대 브랜드 컬러 시스템**
- **기본 화이트 (White)**: `FFFFFF` (프리미엄 배경 및 텍스트)
- **기본 블랙 (Black)**: `000000` 또는 `18181B` (깊은 차콜 블랙, 메인 텍스트 및 대비가 필요한 영역)
- **메인 골드 (DONG-A Main Gold)**: `9D7F6E` (RGB: 157, 127, 110 / METALLICS 8042 C) - 주요 강조, 띠지, 아이콘, 굵은 타이틀
- **서브 컬러 (DONG-A Sub Color)**: `E0A6AD` (RGB: 224, 166, 173 / PANTONE 3519 C) - 포인트 영역, 박스 배경, 보조 강조
- **메탈릭 로즈 골드 (DONG-A Metalic Rose Gold)**: `E6B8BE` (KURZ COLOR SYSTEM LUXOR ALUFIN 769 파우더핑크) - 프리미엄 하이라이트, 선, 장식 요소

### 2.2 Typography (폰트 구조) - 밝은 배경에 맞춘 텍스트 컬러 조정
- 패밀리: `Pretendard` (또는 환경에 맞춘 산세리프 기본체, V10 개편안)
- **절대 폰트 크기 규칙 (Overflow 방지)**:
  - 메인 제목: Text 크기 24~28, bold: true, color: '000000' (검정)
  - 부제목 및 섹션 타이틀: Text 크기 14~16, color: '9D7F6E' (메인 골드), bold: true
  - 본문 (어두운 배경 Box 내부): Text 크기 10~12, color: 'FFFFFF'
  - 본문 (밝은 배경 영역): Text 크기 10~12, color: '000000' 또는 '18181B'
  - 텍스트 오버플로우 방지를 위해 가능한 `wrap: true` 속성을 추가합니다.

### 2.3 레이아웃 제어 (좌표 단위 강제 조항)
**[🚨 V8 QA 최우선 검수 항목] 단 1px의 오프셋 겹침/찌그러짐도 허용하지 않습니다.**
- **기본 단위**: 무조건 `%` 단위의 String으로만 작성. (예: `x: '10%'`) inch 단위 혼용 적발 시 즉시 전면 거부.
- **Y좌표 고정 법칙 (Fixed Header 및 오버랩 방지)**: 
  - メ인 제목이 긴 경우 두 줄로 넘어갈 수 있으므로, 메인 제목은 `x: '5%', y: '8%', h: '12%'`를 할당합니다.
  - 소제목(Subtitle)은 간격을 충분히 띄워 `y: '22%', h: '6%'`에 배치하여 **절대 메인 제목과 겹치지 않게(No Overlapping)** 합니다. 메인 내용 시작(Line)은 `y: '30%'` 부근에 고정합니다.
- **바운더리 준수 (Safe Area limits)**: 어떤 컨텐츠도 슬라이드 하단(`y + h > 95%`)이나 우측(`x + w > 98%`) 밖으로 뚫고 나가지 않도록 크기(`h`, `w`)를 엄격히 통제합니다.
- **단어 보호 (Word-break Control)**: 문장 끝의 한두 글자만 애매하게 다음 줄로 뚝 떨어져서 줄 바꿈되는 현상(단어 보호 안됨)을 **치명적 결함**으로 간주합니다. 이를 막기 위해 **텍스트에 반드시 명시적으로 문맥에 맞게 `\n`을 삽입하여 강제 줄바꿈(수동 워드랩)**을 실시합니다.
- **이미지 종횡비 왜곡 금지 (Aspect Ratio Protection)**: 실사 이미지를 `addImage`로 담을 때, 할당된 `w`와 `h`의 비율(실제 16:9 캔버스 기준)이 현저히 깨져서 찌그러지지 않도록 합리적인 면적 비율을 설정합니다. `sizing: { type: 'cover' }` 또는 `contain`을 올바르게 사용합니다.

## 4. 모듈 구조 템플릿 (PptxGenJS)
```javascript
// src/slides/slide01.js
const slide01 = (pptx) => {
  let slide = pptx.addSlide();
  slide.background = { color: '0A0A0A' };

  // 제목 추가
  slide.addText([
      { text: "THE SHIFT", options: { bold: true, color: 'FFFFFF' } },
      { text: " FROM IN TO ON", options: { bold: true, color: 'B76E79' } }
  ], {
      x: '10%', y: '30%', w: '80%', h: '20%', fontSize: 44, align: 'center'
  });

  // 본문, 도형 등등 추가...
};
module.exports = slide01;
```

## 5. 룰북 무결성 및 자동 진행 (Auto-Proceed) 정책
- 1장부터 13장까지 사용자가 멈추기를 원하지 않는 한, **AI 자신이 중간 개입(사용자 응답 대기)을 생략**하고 내부 턴을 지속 소비하여 스크립트 파일들을 연속적으로 생성해 나갑니다.

## 6. 에이전트 페르소나 (다중 검수 시스템)
완벽한 한 장을 뽑아내기 위해, AI는 내부적으로 다음 두 가지 팀의 역할을 순차적으로 수행하며 코드를 작성하고 검수합니다.

### 👑 1. 품질관리팀 (QA & Design Review Team)
- **역할**: 코드 퀄리티 검토 / 오류 최소화 / 구조적 개선안 도출 / 디자인(인포그래픽/픽토그램/비율/색상) 퀄리티 검수
- **🚨 4대 필수 레이아웃 점검(Layout Integrity Checklist)**: 코드를 반환하기 전, 반드시 다음 4가지 수학적/시각적 계산이 맞는지 자체 검증합니다.
  1. **오버랩 절대 방지 (No Overlapping)**: 도형(`Shape`)과 글상자(`Text`)의 `x`, `y`, `w`, `h` 범위를 계산하여 서로 침범하거나 겹치지 않게 여백(Margin)을 둡니다.
  2. **슬라이드 타이틀 고정 (Fixed Header)**: 슬라이드 제목은 항상 `y: '10%'` 위치에, 소제목은 `y: '18%'` 부근에 고정하여 페이지가 넘어가도 제목 라인이 춤추지 않게(Jumping 현상 방지) 합니다.
  3. **바운더리 준수 (Safe Area limits)**: 어떤 컨텐츠도 슬라이드 하단(`y + h > 95%`)이나 우측(`x + w > 98%`) 밖으로 뚫고 나가지 않도록 크기(`h`, `w`)를 엄격히 통제합니다.
  4. **완벽한 얼라인먼트 및 균형 보장 (Pixel-perfect Alignment & Box Padding)**: 
     - **정렬**: 나란히 있는 도형/텍스트는 상단(`y`값 동일), 좌측(`x`값 정렬), 혹은 중앙 정렬이 수학적으로 완벽해야 합니다.
     - **균형(Padding)**: 도형/글상자 내부의 글자 위치(`align: center, valign: middle`)가 쏠리지 않고 중앙이나 좌측 단락에 예쁘게 안착되어 있는지 위/아래 여백 균형을 살펴봅니다.
- **수행 시점**: 코드를 작성하는 중 혹은 작성 직후 스스로 자체 리뷰를 진행하여 "위 4가지 레이아웃 원칙이 어긋나지 않았는지" 수식 검증을 거칩니다. 통과하지 못하면 즉시 자체 반려 및 `x`, `y`, `w`, `h` 수치를 교정합니다.

### 🧪 2. 테스트팀 (Test & Validation Team)
- **역할**: 기능 테스트 / 렌더링 오류 진단 / 화면 구동 확인 (내부 브라우저 도구 활용)
- **수행 시점**: 컴포넌트 작성이 완료되면 실제 브라우저 에이전트를 가동해 화면이 잘 뜨는지 크로스체크합니다. 레이아웃이 화면 밖으로 삐져나가거나 아이콘이 깨지지 않는지 꼼꼼히 진단합니다.
